## 3. 관리자 계정 만들기  ✅ 완료

### 3-1. 로그인 계정 생성
1. 왼쪽 메뉴 **Authentication** → **Users** → **Add user** → **Create new user**
2. 이메일과 비밀번호 입력, **Auto Confirm User 를 켜십시오**
3. 담당자가 여러 명이면 사람 수만큼 만드십시오 (계정 공유는 하지 마십시오)

### 3-2. 관리자 명단에 등록
**SQL Editor** 에서 아래를 실행합니다. 이메일만 본인 것으로 바꾸십시오.

```sql
insert into public.admin_users (user_id, email, name, role)
select id, email, '박종윤 원장', 'owner'
  from auth.users where email = '원장님이메일@example.com'
on conflict (user_id) do update set role = excluded.role, name = excluded.name;
```

직원 계정은 `'owner'` 대신 `'staff'` 로 넣으십시오.
`owner` 만 신청 내역 삭제와 열람기록 조회가 가능합니다.

### 3-3. 아무나 가입하지 못하게 막기
**Authentication** → **Sign In / Providers** → **Email** →
**Allow new users to sign up** 을 **끄십시오.** (이것을 빠뜨리면 누구나 계정을 만들 수 있습니다.
단, 계정을 만들어도 `admin_users` 에 없으면 신청 내역은 못 봅니다. 그래도 반드시 끄십시오.)

  `절대 스팸으로 신고하지 않음` + `항상 중요 메일로 표시` + 라벨 `상담신청`

1. Resend → **Domains** → **Add Domain** → `mdmiraecell.com`

## 8. 프로젝트가 멈추지 않게 하기  ⚠ 두 번 멈췄습니다 — 꼭 읽어 주십시오

### 8-0. 무슨 일이 있었나

| 시기 | 상태 |
|---|---|
| 2026년 9월 말 ~ 10월 중순 | 약 **4주간** 멈춤 |
| 2026년 10월 28~31일 ~ 11월 9일 | 약 **10일간** 멈춤 |

멈춘 동안에는 **홈페이지 예약·문의가 한 건도 저장되지 않습니다.**
환자분께는 "접수되지 않았습니다 · 02-776-8768로 전화 주십시오" 만 보입니다.
몇 건이 날아갔는지는 알 수 없습니다. 기록 자체가 남지 않기 때문입니다.

### 8-1. 왜 keepalive 가 막지 못했나

[공식 문서](https://supabase.com/docs/guides/platform/free-project-pausing) 는 이렇게 말합니다.

> Free plan 프로젝트는 지난 한 주 동안 충분한 **사용자 데이터베이스 활동**이 없으면
> 비활성으로 간주됩니다. **사용자 쿼리가 너무 적은** 프로젝트가 가장 먼저 중단 대상입니다.
> 보통 **하루에 몇 번씩** 데이터베이스에 요청이 있으면 중단을 피할 수 있습니다.

처음 만든 keepalive 는 이 기준을 **둘 다** 못 맞췄습니다.

| 문서가 요구하는 것 | 처음 만든 것 |
|---|---|
| 하루에 몇 번 | **3일에 한 번** |
| 데이터베이스 쿼리 | 권한 없는 표를 불러 **401 로 막힘** |

두 번째가 치명적이었습니다. 401 은 권한 검사에서 걸러져 **쿼리로 집계되지 않습니다.**
그런데 그 401 을 "정상 — 살아 있습니다" 로 처리하고 있었습니다.
**깨우고 있다고 보고하면서 실제로는 깨우지 않았던 것입니다.**

### 8-2. 지금은 이렇게 고쳤습니다

- **하루 세 번** 실행합니다 (한국시간 10:17 / 18:43 / 02:29)
- 아무 내용도 없는 `public.health` 표를 **실제로 읽습니다.**
  200 이 와야 통과시킵니다. 401·403 은 이제 **실패로 처리합니다**
- 실패하면 **GitHub 이슈를 자동으로 열어** 메일이 갑니다.
  네 번 연속 조용히 실패하는 동안 아무도 몰랐던 일이 없도록
- 정상으로 돌아오면 그 이슈를 자동으로 닫습니다

### 8-3. 설치

**1) 표 만들기** — SQL Editor 에서 아래를 실행하십시오. 한 번만 하면 됩니다.

```
supabase/migrations/20261109000001_keepalive_health.sql
```

> 이 표는 로그인하지 않은 사람도 읽을 수 있습니다. 그래야 쿼리로 집계됩니다.
> 그러므로 **어떤 정보도 이 표에 넣지 마십시오.** 줄 하나, 숫자 하나뿐입니다.

**2) 시크릿 등록** — **저장소 Settings → Secrets and variables → Actions**

| 이름 | 값 |
|---|---|
| `SUPABASE_URL` | 5번의 주소 |
| `SUPABASE_ANON_KEY` | 5번의 공개 키 |

**3) 확인** — **Actions 탭 → Supabase keepalive → Run workflow**

실행 기록에 `응답 코드: 200` 과 `정상 — 쿼리가 수행되었습니다` 가 보여야 합니다.
`401` 이나 `404` 가 보이면 1번을 실행하지 않으신 것입니다.

### 8-4. 솔직히 말씀드릴 것

**이렇게 고쳐도 다시 안 멈춘다고 보증은 못 합니다.**

문서가 "보통 하루 몇 번이면 충분하다" 고 할 뿐, 정확한 기준을 공개하지 않습니다.
10월에도 "3일마다면 된다" 고 보고 틀렸습니다. 최소 일주일은 지켜봐야 압니다.

확실한 방법은 하나뿐이고, 문서에 분명히 적혀 있습니다.

> 유료 플랜의 프로젝트는 **중단될 수 없으며**, 비활성에 따른 자동 중단 대상이 아닙니다.

## 10. 개인정보 관련 — 넘기지 말고 확인하십시오

데이터베이스에 환자 정보를 저장하는 순간 아래가 **의무**가 됩니다.

1. **동의**: 필수 동의(개인정보)와 별도 동의(건강정보)를 나누어 받아야 합니다 → 폼에 반영돼 있습니다
2. **개인정보처리방침 게시** → `privacy` 페이지 (초안이므로 확정 필요)
3. **보유기간 준수**: 방침에 3년으로 적었다면 3년이 지난 건은 실제로 지워야 합니다

```sql
-- 보관기간이 지난 건 파기 (기본 36개월). 방침에 적은 기간과 반드시 일치시키십시오.
select public.purge_expired_consultations(36);
```

4. **접근 권한 관리**: 퇴사자 계정은 즉시 삭제하십시오

```sql
delete from public.admin_users where email = '퇴사자@example.com';
```

5. **열람 기록 확인** (owner 계정으로)

```sql
select at, email, action, target_id from public.access_logs order by at desc limit 100;
```

## 10-1. 보안 점검에서 계속 뜨는 항목 (정상입니다)

Supabase 대시보드의 **Advisors → Security** 에 아래 세 가지가 계속 표시됩니다.
**셋 다 확인했고, 고치면 오히려 문제가 생기거나 고칠 필요가 없는 항목입니다.**

| 표시되는 내용 | 왜 그대로 두는가 |
|---|---|
| `submit_rate_log` 에 RLS는 켜져 있는데 정책이 없음 | **의도된 설정입니다.** 정책이 없으면 아무도 접근하지 못하고, 접수 함수만 쓸 수 있습니다. 가장 안전한 상태입니다. |
| `is_admin()` / `is_owner()` 를 로그인 사용자가 실행 가능 | **반드시 필요합니다.** 신청 내역 접근 규칙이 이 함수로 판정하므로, 실행 권한을 빼면 관리자 화면이 통째로 막힙니다. 로그인하지 않은 방문자는 이미 차단했습니다. |
| `rls_auto_enable()` 을 실행 가능 | 프로젝트 만들 때 켠 **'자동 RLS' 기능이 Supabase 쪽에서 만든 함수**입니다. 직접 호출해도 오류만 나고 정보가 새지 않습니다. 저희가 만든 것이 아니라 손대지 않았습니다. |

## 11. 자주 생기는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 접수 버튼을 눌러도 "접수되지 않았습니다" | `js/config.js` 가 비어 있음 | 5번 확인 |
| 접수는 되는데 관리자 화면에 안 보임 | `admin_users` 미등록 | 3-2 실행 |
| 로그인은 되는데 "관리자로 등록돼 있지 않습니다" | 같은 원인 | 3-2 실행 |
| 콘솔에 CORS 오류 | `ALLOWED_ORIGINS` 불일치 | 4번 환경변수 확인 |
| 한동안 안 쓰다가 갑자기 접수 실패 | 프로젝트 자동 정지 | 8-5 참고. 대시보드에서 Resume |
| 로그인에서 "비밀번호가 올바르지 않습니다" 가 계속 뜸 | 비밀번호가 아니라 **프로젝트 정지**일 수 있음 | 먼저 대시보드에서 정지 여부 확인 |
| keepalive 가 `401` / `404` 로 실패 | `health` 표가 없음 | 8-3 의 1번 실행 |
| 비밀번호 재설정 메일의 링크를 눌렀는데 설정 화면이 안 열림 | 돌아올 주소가 등록 안 됨 | 12-5 실행 |
| 비밀번호 재설정 메일이 아예 안 옴 | Supabase 기본 발송은 팀원 주소에만 보냄 | 12-4 실행 (Resend 를 SMTP 로 연결) |
| 승인은 됐는데 신청자에게 메일이 안 감 | `RESEND_API_KEY` / `NOTIFY_FROM` 없음 | 12-3 확인. 그동안은 화면에 뜨는 링크를 전화로 불러 주십시오 |
| 대표로 로그인했는데 가입 신청 칸이 안 보임 | `admin_users.role` 이 `owner` 가 아님 | Table Editor 에서 확인 |

## 12. 비밀번호 변경 · 가입 신청 · 승인  ⚠ 설치 필요

비밀번호를 잊어버려도 대시보드에 들어가지 않고 스스로 되찾을 수 있게,
그리고 직원이 늘어날 때마다 전도사님이 계정을 직접 만들지 않아도 되게 한 기능입니다.

### 12-0. 무엇이 생겼는가

| 화면 | 누가 쓰는가 | 하는 일 |
|---|---|---|
| 로그인 화면 › **비밀번호를 잊으셨나요** | 관리자 누구나 | 본인 메일로 설정 링크를 받습니다 |
| 로그인 화면 › **관리자 가입 신청** | 새로 들어온 직원 | 신청만 넣습니다. 계정은 아직 안 생깁니다 |
| 관리자 화면 › **비밀번호 변경** | 로그인한 관리자 | 지금 쓰는 비밀번호를 바꿉니다 |
| 관리자 화면 › **관리자 가입 신청** 칸 | **대표 계정만** | 승인/거절합니다. 승인하면 그때 계정이 만들어집니다 |
| `/admin-reset` | 메일 링크로 들어온 사람 | 새 비밀번호를 직접 정합니다 |

**지켜 둔 것**

- Supabase 의 `Allow new users to sign up` 은 **계속 꺼 둡니다.** 승인될 때만 함수가 계정을 만듭니다.
- 임시 비밀번호는 **아무에게도 알려 주지 않습니다.** 신청자가 메일 링크에서 직접 정합니다.
  메신저나 메일에 비밀번호가 평문으로 남지 않게 하기 위해서입니다.
- 가입 신청 결과는 **언제나 "접수되었습니다"** 로만 답합니다. 이미 관리자인 이메일이어도
  그렇게 답합니다. 안 그러면 밖에서 어느 이메일이 관리자인지 하나씩 찍어 알아낼 수 있습니다.
- 승인으로 만들어지는 계정은 **항상 `staff`** 입니다. 대표(`owner`)로 올리는 것은
  대시보드에서 따로 하셔야 합니다.

### 12-1. 표 만들기

대시보드 **SQL Editor** 에서 아래 파일 내용을 그대로 붙여 넣고 실행하십시오.
한 번만 하면 되고, 여러 번 실행해도 안전합니다.

```
supabase/migrations/20261020000001_admin_signup.sql
```

### 12-2. 함수 두 개 배포

**Edge Functions → Deploy a new function** 에서 이름과 내용을 그대로 넣으십시오.

| 함수 이름 | 파일 |
|---|---|
| `request-admin-access` | `supabase/functions/request-admin-access/index.ts` |
| `approve-admin-access` | `supabase/functions/approve-admin-access/index.ts` |

### 12-3. 함수 환경변수

**Edge Functions → Secrets** 에 아래를 등록하십시오.
`RESEND_API_KEY` · `NOTIFY_FROM` · `NOTIFY_TO` · `IP_SALT` · `ALLOWED_ORIGINS` 는
7번에서 이미 넣으셨다면 그대로 쓰입니다.

| 이름 | 값 | 없으면 |
|---|---|---|
| `ADMIN_URL` | `https://mdmiraecell.com/admin` | 기본값으로 안내 메일에만 영향 |
| `ADMIN_RESET_URL` | `https://mdmiraecell.com/admin-reset` | 기본값 사용 |
| `RESEND_API_KEY` | 7번과 같은 키 | **승인은 되지만 메일이 가지 않습니다** |
| `NOTIFY_FROM` | 7번과 같은 발신 주소 | 위와 같음 |
| `NOTIFY_TO` | 대표 메일 주소 | 신청이 들어와도 알림이 오지 않습니다 |

> 메일이 못 나가도 승인 자체는 되돌리지 않습니다.
> 대신 화면에 **설정 링크가 그대로 표시**되니, 전화로 불러 주시는 편이 안전합니다.
> 메신저로 보내지 마십시오.

### 12-4. 메일 발송 설정  ← 이것부터 해야 '비밀번호를 잊으셨나요' 가 동작합니다

**중요 — 처음 문서에 제가 잘못 적었던 부분입니다.**

'비밀번호를 잊으셨나요' 는 Supabase 가 직접 메일을 보냅니다.
그런데 Supabase 기본 메일 발송에는 공식 문서에 이런 제한이 있습니다.

> 별도의 SMTP 를 설정하지 않으면, Supabase Auth 는 **프로젝트 팀원이 아닌 주소로는
> 메일을 보내지 않습니다.** 다른 주소는 `email_address_not_authorized` 오류가 납니다.
> — [Auth SMTP 문서](https://supabase.com/docs/guides/auth/auth-smtp)

즉 **설정하지 않으면 직원분들은 비밀번호 찾기를 쓸 수 없습니다.**
Supabase 대시보드에 팀원으로 등록된 주소만 받습니다.

해결은 간단합니다. 7번에서 이미 쓰고 계신 **Resend 를 SMTP 로 연결**하면 됩니다.

**Authentication → Emails → SMTP Settings → Enable Custom SMTP**

| 칸 | 값 |
|---|---|
| Host | `smtp.resend.com` |
| Port | `587` |
| Username | `resend` |
| Password | 7번에서 쓰신 Resend API 키 (`re_` 로 시작) |
| Sender email | 7번의 `NOTIFY_FROM` 과 같은 주소 |
| Sender name | `명동미래셀의원` |

> 연결 직후에는 시간당 30통으로 제한됩니다.
> **Authentication → Rate Limits** 에서 올리실 수 있습니다.

설정하지 않으셔도 **승인 메일(12-2 함수)은 정상으로 갑니다.** 그쪽은 Supabase 기본
발송을 쓰지 않고 Resend 로 직접 보내기 때문입니다. 제한을 받는 것은
'비밀번호를 잊으셨나요' 하나뿐입니다.

### 12-5. 돌아올 주소 등록  ← 빠뜨리면 링크가 동작하지 않습니다

**Authentication → URL Configuration → Redirect URLs** 에 아래를 추가하십시오.

```
https://mdmiraecell.com/admin-reset
https://www.mdmiraecell.com/admin-reset
https://intoedu.github.io/mdmiraecell/admin-reset
```

목록에 없는 주소로는 Supabase 가 보내 주지 않고 기본 주소로 돌려보냅니다.
그러면 링크를 눌러도 비밀번호 설정 화면이 열리지 않습니다.

### 12-6. 점검

- [ ] 로그인 화면에 링크 두 개가 보인다
- [ ] **비밀번호를 잊으셨나요** → 메일이 오고, 링크를 누르면 설정 화면이 열린다
- [ ] 팀원이 **아닌** 주소(예: 직원 개인 메일)로도 그 메일이 온다 ← 12-4 를 해야 됩니다
- [ ] 새 비밀번호를 정한 뒤 그 비밀번호로 로그인된다
- [ ] 로그인 후 **비밀번호 변경** 으로 바꾸고, 바꾼 비밀번호로 다시 로그인된다
- [ ] **관리자 가입 신청** 을 넣으면 대표 메일로 알림이 온다
- [ ] 대표로 로그인하면 **관리자 가입 신청** 칸이 보인다
- [ ] 직원(`staff`) 계정으로 로그인하면 그 칸이 **보이지 않는다**
- [ ] 승인하면 신청자에게 메일이 가고, `admin_users` 에 `staff` 로 들어와 있다
- [ ] 같은 자리에서 한 시간에 세 번 신청하면 막힌다

### 12-7. 승인하기 전에

화면에도 적어 두었습니다만, **승인은 환자분의 성함·연락처·상담 내용을 볼 수 있는
권한을 주는 일**입니다. 신청 화면에 적힌 이름과 이메일만 보고 승인하지 마시고,
전화 등 다른 방법으로 본인이 맞는지 한 번 확인해 주십시오.
메일 주소는 누구나 적어 넣을 수 있습니다.
