## 2. 또 멈추지 않게 하는 표 만들기 ⏱ 2분

**SQL Editor** → **New query** → 아래를 붙여넣고 **Run**

저장소의 `supabase/migrations/20261109000001_keepalive_health.sql` 과 같은 내용입니다.

```sql
create table if not exists public.health (
  id   smallint primary key default 1 check (id = 1),
  note text not null default '프로젝트 자동 중단 방지용. 개인정보 없음.'
);

insert into public.health (id) values (1) on conflict (id) do nothing;

comment on table public.health is
  '자동 중단 방지용 확인 표. 로그인 없이 읽힙니다. 어떤 정보도 넣지 마십시오.';

alter table public.health enable row level security;

revoke all on public.health from anon;
revoke all on public.health from authenticated;

grant select on public.health to anon;
grant select on public.health to authenticated;

drop policy if exists health_select_anyone on public.health;
create policy health_select_anyone on public.health
  for select to anon, authenticated using (true);
```

- [ ] 실행했고 `Success` 가 떴다

> **⚠ 이 표는 로그인하지 않은 사람도 읽을 수 있습니다.**
> 그래야 데이터베이스 활동으로 집계됩니다.
> 그러므로 **어떤 정보도 이 표에 넣지 마십시오.** 지금처럼 줄 하나면 충분합니다.

**왜 필요한가**: 기존 keepalive 는 권한 없는 표를 불러 401 로 막히고 있었습니다.
그런 요청은 쿼리로 집계되지 않는데, 그걸 "정상"으로 처리하고 있었습니다.
깨운다고 보고하면서 실제로는 깨우지 않아 두 번 멈췄습니다.

## 5. 비밀번호 찾기 메일이 나가게 하기 ⏱ 5분

**이걸 안 하면 '비밀번호를 잊으셨나요' 가 직원분들에게는 동작하지 않습니다.**

[공식 문서](https://supabase.com/docs/guides/auth/auth-smtp):

> 별도 SMTP 를 설정하지 않으면 Supabase Auth 는 **프로젝트 팀원이 아닌 주소로는
> 메일을 보내지 않습니다.** 다른 주소는 `email_address_not_authorized` 오류가 납니다.

이미 쓰고 계신 **Resend** 를 그대로 연결하면 됩니다. 새로 가입하실 것 없습니다.

**Authentication → Emails → SMTP Settings → Enable Custom SMTP**

| 칸 | 값 |
|---|---|
| Host | `smtp.resend.com` |
| Port | `587` |
| Username | `resend` |
| Password | 쓰시던 Resend API 키 (`re_` 로 시작) |
| Sender email | `NOTIFY_FROM` 과 같은 주소 |
| Sender name | `명동미래셀의원` |

- [ ] 저장했다
- [ ] **Authentication → Rate Limits** 에서 시간당 한도를 확인했다 (연결 직후엔 30통)

> 승인 메일은 이 설정과 무관하게 잘 나갑니다.
> 그쪽은 Supabase 기본 발송을 쓰지 않고 Resend 로 직접 보내기 때문입니다.
> 제한을 받는 것은 '비밀번호를 잊으셨나요' 하나뿐입니다.
